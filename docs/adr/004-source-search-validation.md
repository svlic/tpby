# ADR-004：严格搜索六位 code 并在本地二次校验

- 状态：已接受（已实现）
- 决策时间：约 2026-09-27
- 相关提交：`6ac39dc`

## 背景

Telegram 搜索可能返回模糊结果。业务上同一个 code 不会重复出现，但 source 通常由两个业务对象组成，也允许只有一个对象。错误选择媒体比暂停处理更危险。

开发期间曾采用“最新批次加可配置 10 分钟窗口”，后来在维护者确认 code 唯一后放弃。

## 决策

- Telegram 搜索只使用带引号的六位数字，例如 `"123456"`。
- “编号”字段、六位 code 的边界和 `(验证视频)` 不参与第一层搜索，而在返回结果中本地校验。
- 搜索结果按单消息或 Telegram album 归为业务对象。
- 合法结果允许一至两个业务对象；超过两个时停止处理，不猜测。
- 所有 source media 中必须恰好有一个带 `(验证视频)` caption 的媒体。
- `source_search_limit` 只作为查询上限保护，当前默认值为 100。
- 校验失败属于确定性业务错误，记录 failure。

## 实现

`TelegramApplication._find_source_objects()` 只发送 `"{code}"` 查询。`contains_numbered_code()` 在本地要求结果包含带中英文冒号的“编号”字段、目标六位 code 和合法数字边界；验证视频仍在构建 task 时跨全部候选媒体校验。

## 结果

- 第一层召回不依赖“编号”字段的具体空格格式。
- 二层校验集中承担防止 Telegram 模糊匹配的责任。
- 歧义数据不会被自动发送，但会产生人工处理成本。

## 证据与边界

- **事实：** code 唯一、quoted search 和本地复核由维护者明确确认。
- **事实：** 一至两个对象的边界与现有实现一致；维护者说明业务上几乎总是两个。
- **事实：** 当前代码和测试已经按最终确认的搜索及二层校验顺序对齐。
- **开放项：** album 通过命中消息附近 ID 范围恢复；维护者确认不需要把这个窗口当作严格业务保证。
